# Sprint 1 — 커플 공유 일정관리 (MVP)

> 두 사람(커플)이 일정을 공유·관리하는 서비스. **커플 연결이 앱 사용의 전제**다.
> Kotlin + Spring Boot + JPA(H2) / 레이어드 아키텍처(Controller → Service → Repository).

---

## 한눈에 보기

```
가입/로그인 ──▶ 커플 연결 ──▶ [게이트 통과] ──▶ 일정 등록·조회
   (JWT)        (코드 교환)      (coupled?)        (캘린더)
```

**연결되지 않으면 아무것도 못 한다.** 커플 연결만이 유일하게 열려 있고, 나머지 앱 기능은 막힌다.

---

## 이번 스프린트에서 만드는 것

| # | 기능 | 핵심 한 줄 |
|---|---|---|
| 1 | **회원 / 인증** | JWT(Access·Refresh) 로그인. 이메일은 복원 불가하게 암호화 저장 |
| 2 | **커플 연결** | 내 코드를 상대가 입력 → 상호 확인되면 연결. 한 명당 커플은 하나 |
| 3 | **접근 게이트** | 토큰의 `coupled` 값으로 앱 진입 차단/허용 (DB 조회 없이) |
| 4 | **일정 관리** | 일정 등록·수정·삭제. 공개 범위(나만/공유/커플) 지정 |
| 5 | **일정 조회** | 내 일정 + 커플 일정 + 상대 공개 일정을 캘린더로 통합 |
| 6 | **색상** | 내 일정은 내 색, 커플 일정은 공유 커플색으로 표시 |

---

## 설계의 중심 결정

- **신원은 토큰만 믿는다** — 권한 판단은 항상 JWT에서 도출, 요청 본문의 user id는 신뢰하지 않는다.
- **연결 = 게이트** — "커플인가?"를 매 요청 DB로 묻지 않고 토큰 `coupled` 스냅샷으로 판정, 상태 변화는 짧은 TTL로 수렴.
- **동시성 1건 보장** — 양쪽이 동시에 서로 코드를 넣어도 커플 row는 정확히 하나(비관적 락 + PK 정렬).
- **시각은 UTC** — 저장은 절대시각, 입출력은 오프셋 포함. 시간대 때문에 날짜가 밀리지 않게.
- **도메인은 순수하게** — 상태 전이·검증은 DB 없이 단위 테스트 가능한 순수 객체로.

- **헤어짐 / 커플 해제 / 데이터 삭제** — 2인 전용 앱이라 불필요로 판단, 제외.
